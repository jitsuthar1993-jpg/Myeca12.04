# DigiLocker Document Readiness Guide for ITR and Schemes

DigiLocker preparation is a fit-and-evidence decision for users collecting digital documents; the work is to use issued digital documents while preserving originals and application proof, compare Aadhaar-linked mobile with PAN, and retain issued certificates and downloaded PDFs for follow-up.

## downloaded PDFs case check: reconstruct the answer

Treat downloaded PDFs as part of the final trail, not proof of every earlier answer; the live instruction and the facts in Aadhaar-linked mobile, PAN, and issued certificates still control the DigiLocker service request.

Worked check for DigiLocker: when Aadhaar-linked mobile and PAN identify the applicant differently, correct the inaccurate issuing record first. Use issued certificates only for eligibility status; retain downloaded PDFs with the request acknowledgement.

## DigiLocker: confirm the live route and applicant fit

A useful DigiLocker service request note for users collecting digital documents names the intended outcome, the live route, the fact supported by Aadhaar-linked mobile, and the issue that PAN or issued certificates must settle.

## Users collecting digital documents: map Aadhaar-linked mobile to downloaded PDFs

Before converting files for DigiLocker, note the issuer, relevant date, applicant details, and supported answer for Aadhaar-linked mobile, PAN, issued certificates, and downloaded PDFs.

| PAN | Keep PAN with its issuer and date visible. It should support applicant identity without contradicting the eligibility status shown by issued certificates. |
| issued certificates | Issued certificates is useful only when the application can trace eligibility status back to it. Resolve any incomplete or inconsistent DigiLocker documents for ITR and schemes 2026 detail before submission. |

## issued certificates conflict: decide before upload

If Aadhaar-linked mobile and PAN disagree, the DigiLocker file no longer demonstrates that the identity, status, and requested service are supported; resolve the source record before relying on issued certificates.

For DigiLocker, compare the applicant name and identifier in Aadhaar-linked mobile with PAN. Correct the inaccurate issuing record through its own channel; use issued certificates only for eligibility status. Retain downloaded PDFs with the request acknowledgement.

## DigiLocker service request: evidence limits and retention

The DigiLocker service request should stop when Aadhaar-linked mobile or PAN supports a contradictory material answer; a later submission is preferable to an inaccurate or unreconstructable file.

Users collecting digital documents should not submit merely because every upload slot is filled; the facts in Aadhaar-linked mobile, PAN, and issued certificates must support the same request.
